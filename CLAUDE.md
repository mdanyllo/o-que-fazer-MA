This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

"Descubra Maranhão" — a high-fidelity, **frontend-only visual MVP** of a tourism discovery/trip-planning platform for the state of Maranhão, Brazil. The full product brief (in Portuguese) is in `README.md`; read it before adding features or pages. Key constraints from the brief:

- No backend, auth/login, database, payments, CRUD, admin dashboard, or real external APIs. Everything runs on mocked data with simulated interactions (e.g. the trip planner "generates" a fixed itinerary; the map is a styled simulation, not a real map API).
- No important button without an action; no empty screens; no lorem ipsum.
- Priorities: design/UX, the map, destinations, itineraries, trip planner, responsiveness (a distinct mobile experience, not a shrunk desktop), visual content.
- Avoid generic "AI SaaS" visuals (purple gradients, uniform card grids, tiny cards). Don't add unnecessary dependencies or change project config without need.
- UI copy is in Brazilian Portuguese; route paths are Portuguese (`/destinos`, `/roteiros`, `/planejar`, `/mapa`, `/experiencias`, `/eventos`, `/empresas`).

## Architecture

**Stack:** TanStack Start (SSR, React 19) + TanStack Router (file-based) + Tailwind CSS v4 + shadcn/ui (Radix) + lucide-react icons. `@/` aliases `src/`.

**Build config:** `vite.config.ts` uses `@lovable.dev/vite-tanstack-config`, which already bundles tanstackStart, React, Tailwind, tsconfig paths, nitro, devtools, etc. Do **not** add those plugins manually (duplicates break the app); pass extra options through `defineConfig({ vite: {...} })`.

**Routing:** `src/routes/` is file-based (see `src/routes/README.md` for conventions: `$param` for dynamic segments, `__root.tsx` is the only root layout and must keep `<Outlet />`). `src/routeTree.gen.ts` is auto-generated by the router plugin — never edit by hand. Dot-separated filenames create nesting (`destinos.$slug.tsx` → `/destinos/:slug`, `destinos.index.tsx` → `/destinos`).

Route patterns in use:
- Detail pages (`destinos.$slug`, `roteiros.$slug`) look up mock data in `loader` via `getDestination`/`getItinerary`, `throw notFound()` when missing, and set per-page meta in `head` from `loaderData`.
- Filter state lives in the URL via `validateSearch` + `navigate({ search })` (see `experiencias.tsx`); category cards link into these filtered pages.

**Server entry:** `src/server.ts` wraps TanStack Start's server entry to render a friendly error page for SSR crashes (including h3-swallowed errors); `src/start.ts` registers error + CSRF middleware. `vite.config.ts` points `tanstackStart.server.entry` at it. These are Lovable scaffolding — leave them alone unless necessary.

**Mock data:** `src/data/maranhao.ts` is the single source of content — typed collections (`categories`, `destinations`, `experiences`, `itineraries`, `mapPoints`/`mapTypes`/`mapRoute`, `events`, `businesses`, `searchSuggestions`), lookup helpers, and the `img` map of imported photos from `src/assets/`. Entities cross-reference by slug/id (e.g. `experience.destinationSlug`, `mapRoute.stops` → `mapPoints` ids). Map points use percentage `x`/`y` coordinates on the simulated map, not lat/lng. Prices, ratings, and businesses are demonstrative; don't invent specific factual claims about real places.

**Components:**
- `src/components/site/` — product components. `PageShell` wraps every page (header, footer, mobile floating "Monte minha viagem" CTA) and exports `PageHero`. `cards.tsx` holds the reusable cards (`DestinationCard`, `CategoryCard`, `ExperienceCard`, `RouteCard`, `EventCard`, `BusinessCard`) and `SectionHeading`. `MapExplorer` is the simulated interactive map (filters, zoom, pins, popup, route line; has a `compact` mode). `TripPlanner` is the multi-step wizard with simulated result.
- `src/components/ui/` — shadcn/ui primitives (`components.json`); add new ones via shadcn conventions rather than hand-rolling.

**Design system:** defined in `src/styles.css` (Tailwind v4 `@theme inline`, oklch colors). Beyond shadcn tokens there are brand tokens `sand`, `sand-deep`, `turquoise`, `deep`, `forest`, `gold`; fonts `font-display` (Fraunces, headings) and `font-sans` (Plus Jakarta Sans); shadows `shadow-soft`/`shadow-lift`; and custom utilities `hero-scrim`, `text-balance-title`, `card-lift`, `img-zoom`, `animate-rise`. Use these tokens/utilities instead of ad-hoc colors.
